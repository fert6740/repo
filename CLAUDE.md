# stream-clipper — заметки для Claude Code

Полное задание — `TZ.md` (разделы 1–10 — исходное ТЗ, раздел 11 — дополнения после обсуждения).
Инструкция для пользователя — `README.md`.

## Пользователь

- Отвечать по-русски, кратко. В Linux не разбирается: всё делать самому; команды с `sudo` он вводит сам — давать
  готовой строкой. Ничего не удалять без его согласия.
- Arch Linux, RTX 4060 (свободно ~3 ГБ видеопамяти), 12 потоков, 31 ГБ ОЗУ, ~79 ГБ свободно на диске, интернет через VPN.
- Долгие операции — через `clipper bg ...` (tmux), чтобы переживали закрытие чата.

## Состояние (октябрь 2026)

Этап 1 («темы без видео») написан в облачной сессии, где Twitch, HuggingFace и видеокарта были недоступны.
**На настоящей записи ещё не запускался** — это первое, что нужно сделать на ПК.

Проверено в облаке: автотесты (`tests/`), шаг 1 на синтетическом видео, нагрузка как у 6-часового стрима,
настоящие вызовы `claude -p` (проход 1 с окнами и без, темы из нескольких кусков, сравнение моделей),
поиск плашек донатов на синтетике, страницы в браузере.
Не проверено: скачивание с Twitch, чат (TwitchDownloaderCLI), клипы зрителей (GQL), whisper на видеокарте,
h264_nvenc, `--shutdown`, уведомления.

## Ближайшие шаги на ПК

1. `./install.sh`, затем `clipper doctor` — исправить всё со значком ✘.
2. `clipper llm-probe` — какого размера запрос проходит; поправить `window_tokens`/`chars_per_token` в `config.toml`.
3. Первая запись: `clipper bg run <ссылка> --streamer <имя>` (имя стримера и ссылку спросить у пользователя).
   После — `clipper usage <номер>` (настоящие время и токены; поправить раздел 6 ТЗ), `clipper compare-models <номер>`.
4. Пользователь пришлёт скрины доната (полный кадр) — вырезать плашки в `streamers/<имя>/alerts/`,
   при постоянном месте задать `region` в `[alerts]` его `streamer.toml`.
5. Приёмка этапа 1 — пользователь смотрит темы и подтверждает, что границы осмысленные. Потом этап 2.

## Открытые вопросы к пользователю

1. Ключ YouTube Data API (для обучения на просмотрах) — готов ли завести.
2. Конкуренты: список каналов или искать нарезки по имени стримера.
3. Свободен ли ПК во время стримов (для режима «во время стрима»).
4. Уведомления в Telegram — нужны ли.
5. В режиме стрима выпускать тему сразу, как закончилась (предложено «да»).

Порядок работ, предложенный пользователю: этап 2 (сборка) → страница с галочками и «Собрать» → обучение на
просмотрах → шорты → режим во время стрима → сцены и зумы.

## Разработка

- Окружение: `.venv` (Python 3.12 через uv). Тесты: `.venv/bin/python -m pytest -q tests`; проверка:
  `.venv/bin/python -m pyflakes clipper`. Запуск из исходников: `bin/clipper` или `.venv/bin/python -m clipper`.
- Шаги независимы, повторный запуск не пересчитывает готовое (`--force`), запись файлов атомарная
  (`record.write_json`), время шагов — в `timings.json`, все пороги — в `config.toml`/`streamer.toml`.
- Сообщения пользователю — по-русски; понятные ошибки — через `ClipperError`.

## Принятые решения (не переделывать без причины)

- Нейросеть отдаёт время как `ч:мм:сс`, в секунды переводит код (`topics.to_seconds`).
- `claude -p` запускается из пустой папки в /tmp (вне домашней — иначе подтянется большой `~/CLAUDE.md`),
  со своим `--system-prompt`, без `ANTHROPIC_API_KEY` и `CLAUDECODE*` в окружении (`llm.py`).
- yt-dlp больше не качает чат Twitch → только TwitchDownloaderCLI (скачивается сам в `tools/`).
- Заглушённые куски — из плейлиста записи (сегменты `*-muted.ts`), тишина в звуке — запасной способ.
- Тема может состоять из нескольких кусков: у кусков одной темы одинаковый `key`, `topics.group_topics`
  собирает `parts`. Склейка окон — `topics.merge_windows` (новое окно отвечает за время со своего первого куска).
- Сравнение с конкурентами — с медианой канала в окне ±14 дней, шорты и длинные отдельно (TZ.md, раздел 11).
