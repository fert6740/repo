# ТЗ: stream-clipper — автоматические нарезки из записей стримов

Документ для разработчика (нейросети). Всё, что нужно для работы, написано здесь; предыдущей переписки у тебя нет.

## 1. Цель

Программа получает ссылку на запись стрима Twitch и выдаёт папку готовых роликов:

- **длинные нарезки** по темам (горизонтальные, 4–25 минут) с автоматическим монтажом;
- **шорты** (вертикальные, 20–60 секунд) из самых ярких моментов;
- к каждому ролику — варианты названия, описание и обложки.

На YouTube ролики пользователь загружает сам. Первая цель — один стример и одна запись, доведённые до смотрибельного результата. Масштабирование на десятки стримеров — потом, но архитектура не должна ему мешать (всё, что зависит от стримера, лежит в его папке настроек).

## 2. Что входит в первую версию и что нет

Входит: скачивание записи и чата, распознавание речи, поиск тем нейросетью, план монтажа, вырезание пауз и блоков с донатами, приближение вебки, интро, шорты, обложки, страница подтверждения плана, учёт расхода токенов.

Не входит (не делать, но не закрывать дорогу): автозагрузка на YouTube, другие площадки кроме Twitch, автоматическое слежение за новыми стримами, распознавание музыки, одновременная обработка многих стримеров.

Не делать вообще: «второй канал с теми же роликами и другими зумами». Два продукта из одного стрима — это длинные нарезки и шорты.

## 3. Окружение

- Arch Linux, один ПК пользователя. Пользователь в Linux не разбирается: всё делать самому, команды с `sudo` он вводит сам (давать готовой строкой). Ничего не удалять без его согласия. Отвечать по-русски, кратко.
- Железо: RTX 4060 (8 ГБ видеопамяти, из них около 5 ГБ постоянно занято рабочим столом — **свободно примерно 3 ГБ**), 12 потоков, 31 ГБ памяти.
- **Диск: свободно около 79 ГБ.** Запись на 6 часов в 1080p60 — 15–25 ГБ. Перед скачиванием проверять место (нужно не меньше двух размеров записи), иначе останавливаться с понятным сообщением.
- Установлено: `ffmpeg` (есть `h264_nvenc`, `hevc_nvenc`), `ffprobe`, `tmux`, Python 3.14, `claude` (Claude Code 2.1.295, вход по подписке).
- Не установлено: `yt-dlp`, `uv`. Ставить в окружение проекта, а не в систему, где это возможно.
- Python-зависимости — в отдельном виртуальном окружении проекта. Если для Python 3.14 нет готовых сборок `ctranslate2`/`faster-whisper`/`opencv`, взять Python 3.12 через `uv`.
- Весь трафик идёт через VPN; скорость скачивания может быть ниже обычной.
- Долгие операции запускать так, чтобы они переживали закрытие чата (`tmux`), и писать журнал в файл.

## 4. Устройство

Конвейер из независимых шагов. Каждый шаг читает файлы предыдущего и пишет свои. Правила для всех шагов:

- **Повторный запуск ничего не пересчитывает**, если результат уже есть (ключ `--force` пересчитывает).
- Все решения о монтаже сначала попадают в файл **плана** (`plan.json`), видео собирается только по плану. Нейросеть никогда не трогает видео напрямую.
- Все пороги и числа из этого ТЗ — стартовые значения, вынести в настройки.
- Каждый шаг пишет время работы в `timings.json`.

```
stream-clipper/
  TZ.md
  config.toml                  общие настройки
  clipper/                     код (Python-пакет, запуск: clipper <команда>)
  streamers/<стример>/
    streamer.toml              настройки стримера
    scenes.json                разметка сцен
    intro.mp4                  интро (может отсутствовать)
    refs/                      опорные кадры сцен
  data/<стример>/<id записи>/  рабочая папка одной записи
    source.mp4  proxy.mp4  chat.json  audio.wav
    transcript.json  signals.parquet  scene_track.json
    topics.json  plans/<клип>.json  llm_usage.jsonl  timings.json
    out/<NN название>/         готовые ролики
```

Папка `data/` должна настраиваться (может переехать на другой диск).

### Шаг 1. Скачивание

- Запись: `yt-dlp`, качество по настройке (по умолчанию не выше 1080p).
- Чат записи: проверить `yt-dlp --write-subs --sub-langs rechat`; если не работает — `TwitchDownloaderCLI chatdownload`. Сохранить как `chat.json`: время от начала записи, автор, текст.
- Сразу сделать `proxy.mp4` (360p, частые ключевые кадры) — для быстрых перемоток на странице подтверждения, и `audio.wav` (16 кГц моно) для распознавания.
- Twitch глушит в записях куски с чужой музыкой. Найти отрезки с цифровой тишиной при движущейся картинке и записать их: темы, которые на них попадают, помечаются «звук вырезан Twitch».

### Шаг 2. Распознавание речи

- `faster-whisper`, модель по умолчанию `large-v3-turbo`, язык `ru`, время каждого слова (`word_timestamps`), фильтр тишины (VAD) включён. Тип вычислений подобрать под 3 ГБ свободной видеопамяти (`int8_float16`), при нехватке — понятная ошибка, а не падение.
- Whisper на тишине и музыке выдумывает текст: отбрасывать отрезки с низкой уверенностью и высокой вероятностью «нет речи», повторяющиеся подряд одинаковые фразы.
- `transcript.json`: отрезки `{start, end, text, words: [{start, end, word, prob}]}`.

### Шаг 3. Сигналы (ряд значений раз в секунду)

Всё сохраняется в `signals.parquet`, каждый сигнал — и исходное значение, и отклонение от обычного уровня (относительно скользящей медианы за 10 минут).

| Сигнал | Как считать |
|---|---|
| Громкость | Среднеквадратичная громкость `audio.wav` по секундам |
| Речь | Доля секунды, занятая словами из распознавания |
| Чат | Сообщений за 10 с; отдельно — доля «смеховых» сообщений (список слов и смайлов в настройках стримера). Чат реагирует с опозданием 5–15 с — сдвиг в настройках |
| Движение вебки | Средняя разница соседних кадров внутри прямоугольника вебки |
| Движение экрана | То же по остальному кадру, без вебки, чата и плашки донатов |
| Плашка доната | Активность в прямоугольнике плашки (если он размечен) |
| Сцена | Номер сцены из шага 4 |

Видео для этого декодировать уменьшенным (320×180, 4 кадра/с, серое), с аппаратным декодированием — полный кадр не нужен.

### Шаг 4. Сцены

Сцена — это раскладка кадра: где вебка, где чат, где появляются донаты.

**Разметка (один раз на стримера):** команда `clipper scenes-setup <стример> <запись>` берёт из записи около сотни кадров, группирует похожие раскладки и открывает локальную страницу. На ней пользователь для каждой раскладки мышью обводит прямоугольники «вебка», «чат», «плашка доната», даёт сцене имя и тип. Результат — `scenes.json`:

```json
{"scenes": [{
  "id": "game", "name": "Игра, вебка в углу",
  "type": "game_cam_corner",
  "webcam": [0.78, 0.70, 0.21, 0.28],
  "chat": [0.0, 0.55, 0.18, 0.45],
  "alert": [0.35, 0.02, 0.30, 0.18],
  "zoom_allowed": true,
  "anchors": [{"rect": [0.77, 0.69, 0.23, 0.02], "ref": "refs/game_a1.png"}]
}]}
```

Координаты — доли кадра (0–1). Типы: `game_cam_corner` (маленькая вебка в углу), `full_cam` (вебка на весь экран, «просто общение»), `brb` (заставка «скоро вернусь»), `other`.

**Определение сцены в каждый момент:** раз в секунду кадр сравнивается с опорными кусочками (`anchors` — неподвижные элементы оформления: рамка вебки, подложка чата). Побеждает сцена с лучшим совпадением выше порога; запасной признак — лицо найдено в прямоугольнике вебки этой сцены. Сглаживание: сцена считается сменившейся, если держится не меньше 3 секунд. Если ни одна не подошла — `unknown`: на таких отрезках зумы не делаются, а в отчёте пишется, сколько минут не распознано (сигнал доразметить).

Отрезки типа `brb` в нарезки не попадают никогда.

### Шаг 5. Темы (нейросеть)

Обращение к нейросети — через один модуль `llm.py` с двумя взаимозаменяемыми способами (переключатель в настройках):

1. **`claude_cli` (используется сейчас, по подписке):** запуск `claude -p --model <haiku|sonnet|opus> --output-format json --json-schema '<схема>' --tools "" --strict-mcp-config --no-session-persistence`, текст запроса — через стандартный ввод.
   - Рабочая папка процесса — пустая временная папка **вне домашней папки**, иначе подтянется большой `~/CLAUDE.md` пользователя и съест токены.
   - `--bare` не использовать: в этом режиме вход по подписке не читается.
   - Из ответа брать результат и расход токенов.
2. **`anthropic_api` (на будущее):** официальный пакет `anthropic`, ключ из переменной окружения. Сейчас достаточно заглушки с тем же интерфейсом.

**Первым делом проверить**, какого размера запрос проходит через `claude -p` (отправить текст известной длины). От этого зависит размер окна ниже.

**Что отдаётся нейросети.** Не сырые субтитры, а сжатый текст: реплики склеены в куски по 20–30 секунд, время ставится один раз на кусок (`[1:23:40]`), внутрь вставлены короткие пометки из сигналов: `⟨чат ×3⟩`, `⟨смех в чате⟩`, `⟨крик⟩`, `⟨донат⟩`, `⟨тишина 40с⟩`, `⟨сцена: игра⟩`, `⟨звук вырезан⟩`.

**Проход 1 — карта стрима.** Если текст всего стрима помещается в один запрос — один запрос на весь стрим. Если нет — окна с перекрытием 10 минут; каждому следующему окну передаётся краткий пересказ предыдущих (до ~1500 токенов) и незакрытая тема («тема „…“ началась в 2:47:10 и не закончена»), после чего темы на стыках склеиваются. Тема не должна рваться на границе окна — это обязательная проверка.

Ответ (строго по схеме):

```json
{"topics": [{
  "id": 7, "start": 5025, "end": 5890,
  "title": "рабочее название", "summary": "2–3 предложения",
  "kind": "story | gameplay | discussion | reaction | donations_block | pause | tech | other",
  "score": 8, "why": "почему это интересно зрителю",
  "self_contained": true
}],
"shorts": [{"start": 5310, "end": 5352, "hook": "первая фраза", "score": 9, "why": "..."}]}
```

`self_contained` — понятна ли тема без остального стрима. В работу идут темы с оценкой не ниже порога (по умолчанию 6), длительностью 4–25 минут, не `donations_block`/`pause`/`tech`, без пометки «звук вырезан».

**Проход 2 — монтаж одной темы.** Для каждой отобранной темы отдельный запрос: подробный текст темы (время на каждую реплику) плюс по 2 минуты до и после. Ответ:

- уточнённые начало и конец (тема начинается с понятной фразы, а не с середины мысли);
- список кусков на удаление с причиной: `donation` / `offtopic` / `dead_air` / `tech` / `repeat`;
- 5 вариантов названия, описание, 2–3 слова для обложки, момент для кадра обложки;
- момент на 5–10 секунд для тизера в самом начале ролика (необязательно).

**Правило про донаты** (сформулировать в запросе именно так):
- стример остановился и отвечает на донаты не по теме — вырезать весь блок, от начала озвучки доната до возврата к теме;
- донат по теме ролика — оставить;
- донат звучит поверх происходящего, а стример не прерывается — оставить (вырезание сломает сам момент).

**Привязка границ.** Любая граница (начало, конец, вырезаемый кусок) после ответа нейросети сдвигается к ближайшей паузе между словами длиной от 0,3 с в пределах ±3 с. Резать посреди слова нельзя. Это делает код, а не нейросеть.

**Сравнение моделей.** Команда `clipper compare-models <запись>` прогоняет проходы 1 и 2 тремя моделями (`haiku`, `sonnet`, `opus`) и собирает одну страницу: темы каждой модели рядом на общей шкале времени, оценки, названия, расход токенов. По ней пользователь выберет модель (возможно, дешёвую для прохода 1 и сильную для прохода 2). До этого решения модель по умолчанию — `opus`.

### Шаг 6. План монтажа

На каждый ролик — `plans/<клип>.json`. Время везде — секунды исходной записи.

```json
{"clip_id": "t07", "type": "long", "title": "…",
 "keep": [[5031.2, 5210.0], [5266.4, 5884.9]],
 "removed": [{"range": [5210.0, 5266.4], "reason": "donation"}],
 "zooms": [{"range": [5102.0, 5105.5], "rule": "shout"}],
 "teaser": [5540.0, 5547.5], "intro": "streamers/x/intro.mp4",
 "thumb": {"time": 5544.0, "text": "ДВА СЛОВА"},
 "approved": false}
```

**Вырезание пауз** (внутри оставленных кусков). Кусок убирается, если одновременно: речи нет дольше 1,5 с; движение экрана ниже обычного; нет громких звуков; чат не на всплеске. По краям оставлять по 0,25 с. Если на экране идёт действие (игра) — тишина остаётся. В отчёте писать, какая доля ролика вырезана как паузы; если больше 30 % — помечать ролик на проверку.

**Приближение вебки.** Только в сценах с `zoom_allowed` (тип `game_cam_corner`). Правила:

| Правило | Условие | Длительность |
|---|---|---|
| `shout` — крик | громкость сильно выше обычной (от 2,5 отклонений) при наличии речи, не меньше 0,7 с | 2–4 с |
| `static_screen` — экран стоит, вебка живая | движение экрана низкое не меньше 3 с, движение вебки заметно выше обычного | пока держится, до 8 с |
| `silent_idle` — молчит и ничего не происходит | нет речи и экран стоит от 2 с, а кусок не вырезан как пауза | до 4 с |

Ограничения: между зумами не меньше 6 с; суммарно не больше 25 % ролика; плавный вход и выход по 0,2 с. Вид зума: вебка увеличивается примерно до 60 % высоты кадра по центру, под ней исходный кадр, затемнённый и размытый. На весь экран не растягивать — вебка маленькая, выйдет мыло. Вид и размер — в настройках стримера.

### Шаг 7. Подтверждение плана

`clipper review <запись>` открывает локальную страницу (только `127.0.0.1`): список тем и шортов с временем, длительностью, названием, оценкой, пересказом; у каждой — галочка, проигрыватель по `proxy.mp4` с полосой, где цветом показаны вырезанные куски и зумы; можно поправить название и сдвинуть начало и конец. Кнопка «Собрать выбранные» ставит `approved` и запускает сборку. В настройках — порог оценки, выше которого темы подтверждаются сами (по умолчанию выключено).

### Шаг 8. Сборка видео

- `ffmpeg`, кодирование `h264_nvenc`, 1080p, частота кадров как у исходника, звук AAC 192 кбит/с, выравнивание громкости до −14 LUFS.
- Порядок: тизер (если есть) → интро (если есть, привести к тем же размеру и частоте кадров) → тема.
- Резать с перекодированием (точные границы), длинные ролики собирать по кускам и склеивать — не строить один гигантский граф фильтров.
- **Шорты:** 1080×1920. Для `game_cam_corner`: сверху вебка (около 40 % высоты), снизу центральная часть игры. Для `full_cam`: обрезка по центру. Крупные субтитры по словам (из времени слов), по 2–4 слова на экране.
- **Обложки:** 1280×720, три варианта: кадр в момент `thumb.time`, вебка увеличена, фон — тот же кадр с размытием, 2–3 слова крупно с обводкой.
- Результат: `out/<NN название>/` — `video.mp4`, `thumb_1..3.jpg`, `meta.txt` (названия, описание, таймкоды глав), копия плана.

## 5. Команды

```
clipper run <ссылка> --streamer <имя>     всё до страницы подтверждения
clipper download|transcribe|signals|scenes|topics|plan <запись>   отдельный шаг
clipper scenes-setup <стример> <запись>   разметка сцен
clipper review <запись>                   страница подтверждения
clipper render <запись> [--only t07,s03]  сборка подтверждённого
clipper compare-models <запись>           сравнение моделей
clipper usage <запись>                    расход токенов и времени
clipper clean <запись>                    удалить исходник и временные файлы (только по явной команде пользователя)
```

Каждая команда печатает, что сделано, сколько заняло и где лежит результат.

## 6. Расход токенов

Оценка для записи на 6 часов (проверить на первой же записи и поправить этот раздел):

| | На вход | На выход |
|---|---|---|
| Проход 1 (весь стрим) | ~150 тыс. | ~10 тыс. |
| Проход 2 (около 15 тем) | ~80 тыс. | ~20 тыс. |
| **Всего на стрим** | **~230 тыс.** | **~30 тыс.** |

Откуда: около 40 тыс. слов речи за 6 часов, русское слово — примерно 3 токена, плюс время и пометки. Размышления модели считаются как выход и могут удвоить правую колонку.

По подписке деньги не списываются, тратятся лимиты. Для сравнения, по ценам API (за 1 млн токенов вход/выход): Opus 5.5 — 4 $/20 $, около 1,5 $ за стрим; Sonnet 5.5 — 2 $/10 $, около 0,75 $; Haiku 5.5 — 0,10 $/0,50 $ (для запросов длиннее 100 тыс. токенов — 0,50 $/2,50 $), около 0,10–0,15 $.

Обязательно:

- каждое обращение к нейросети пишет строку в `llm_usage.jsonl`: шаг, модель, токены на вход и выход, время;
- `clipper usage` показывает итог по записи и пересчёт в цены API;
- меры экономии: время один раз на кусок 20–30 с; мусорные отрезки распознавания не отправлять; проход 2 только для отобранных тем; неизменную часть запроса (инструкции) держать в начале и одинаковой.

## 7. Настройки

`config.toml`: папка данных, качество скачивания, модель распознавания, способ обращения к нейросети и модель для каждого прохода, размер окна, все пороги из шагов 3–6.

`streamers/<имя>/streamer.toml`: логин на Twitch, язык, путь к интро, вид зума, допустимая длительность нарезок и шортов, «смеховые» слова и смайлы чата, сдвиг чата, примеры удачных названий роликов этого стримера (уходят в запрос как образец стиля), темы, которые не брать.

## 8. Порядок работы и приёмка

Делать этапами, каждый показывать пользователю на настоящей записи, не переходить дальше без рабочего результата.

1. **Темы без видео.** Шаги 1–3 (без видеосигналов) и проход 1; страница со списком тем и шортов; `usage`; `compare-models`. *Готово, если:* по записи получен список тем с временем, пользователь открыл несколько и согласен, что границы осмысленные; известен настоящий расход токенов.
2. **Простая нарезка.** Проход 2, план, вырезание пауз и донатов, интро, выравнивание громкости, сборка длинных роликов. *Готово, если:* ролик смотрится без обрывов на полуслове, блоки ответов на донаты убраны, звук и картинка не расходятся.
3. **Сцены и зумы.** Разметка, определение сцен, видеосигналы, приближение вебки. *Готово, если:* сцены определяются верно не меньше чем на 95 % проверенных вручную моментов; зумы срабатывают на крик и на «экран стоит» и не срабатывают вне сцены с вебкой в углу.
4. **Шорты, обложки, описания.**
5. **Страница подтверждения целиком, обработка нескольких записей подряд.**

Проверка каждого собранного ролика кодом: есть видео и звук, длительность равна сумме оставленных кусков (±0,5 с), нет ошибок декодирования в конце файла.

## 9. Известные сложности

- Маленькая вебка даёт мягкую картинку при увеличении — поэтому 60 % кадра, а не весь экран.
- Стример может сменить оформление — отсюда сцена `unknown` и отчёт о нераспознанных минутах.
- Озвучка донатов синтезированным голосом тоже попадает в распознавание; отличать её от речи стримера помогает сигнал плашки доната.
- Записи на Twitch хранятся ограниченное время и местами заглушены.
- Разрешение стримера на нарезки и претензии по музыке — забота пользователя, не кода; код только помечает заглушённые отрезки.

## 10. Чего не хватает для старта

От пользователя нужны: имя стримера и ссылка на одну его запись; интро (файл), если оно есть.
